## 项目代码审计（扫地机器人智能客服 Agent）

- 技术语言构成：**纯 Python**（20 个 .py，1954 行），配套 SQL（SQLite DDL）、YAML 配置 5 个、纯 HTML+CSS 报告页（无 JS）、Markdown、Mermaid。前端由 Streamlit 生成，无独立前端语言。
- 完成一次全量代码走读，产出分级优化清单（P0 正确性 / P1 架构性能 / P2 工程化）。

### 审计确认的问题（后续修的时候可直接对号入座）

**P0**
1. `README.md` 有未解决的 Git 冲突标记：第 1 行 `<<<<<<< HEAD`、420 行 `=======`、423 行 `>>>>>>> 1f55cfb...`。
2. `agent/tools/agents_tools.py` `get_weather()` 把「最近6小时降雨概率极低」**硬编码**在返回串里，与 wttr.in 实际数据无关 → 事实性错误。
3. 报告模式无法自动退出：`ReactAgent.finish_report()` 全项目只在 `react_agent.py` 的 `__main__` 测试里调用，`app.py` 从未调用 → 用户一旦生成报告，后续所有提问都走报告提示词。且 mode 存在两处真相（middleware 全局 dict vs `conversations.mode`），互不同步。
4. `.env.example` 写「复制为 .env 后填入真实值」，但全项目无 `python-dotenv` 依赖、无 `load_dotenv()` 调用 → 照文档操作会鉴权失败。
5. 会话历史无截断/窗口管理，长会话 token 线性膨胀；`SessionStore.save_conversation()` 每步 **DELETE + 全量 re-INSERT**，单轮对话内被调用 2~10 次 → O(n²) 写放大。
6. `react_agent.py` 把原始异常 `f"抱歉，模型服务暂时不可用：{e}"` 直接回吐给终端用户，泄露内部信息。

**P1**
7. `chat()` 与 `chat_stream()` 约 100 行逻辑重复，建议统一（`chat` = 拼接 `chat_stream` 的 text 事件），或直接换 LangGraph `create_react_agent`。
8. SQLite 未开 `PRAGMA journal_mode=WAL` / `busy_timeout`，连接靠 GC 关闭，多 Streamlit 会话并发易 `database is locked`。
9. `ReactAgent` 经 `@st.cache_resource` 全局共享，`self.sessions` 字典多会话并发有竞态。
10. 知识库入库 `VectorStoreService.load_document()` 只在自身 `__main__` 里调用 → 新增文档不会自动入库，需手动执行。
11. 检索参数偏保守：`chunk_size=200`、`k=3`、默认 similarity；建议 chunk 400~600 + MMR 或加 reranker。
12. 中间件「HTTP 服务」模式形同虚设：`react_agent` 与 `app.py` 读的都是本地 `middleware` 模块的全局 dict，本地函数始终是权威来源；且用的是单线程 `HTTPServer`。

**P2**
13. `requirements.txt` 未锁版本，且缺 `dashscope`（`DashScopeEmbeddings` 运行必需）。
14. 3 个测试是手写 `check()` 脚本，未用 pytest，无 CI。
15. `__pycache__/eval_questions.cpython-311.pyc` 存在但 `eval_questions.py` 源码已丢失 → `eval_report.html` / `eval_results.json` 无法复现。
16. 无可观测性：无 token 计费、耗时埋点、trace。
17. `_rag_cache` / `_weather_cache` 无上限；模块级 `external_data` 无锁。
18. 无 Dockerfile、日志无轮转（`logs/` 无限增长）、默认值硬编码 `1001` / `深圳`。
